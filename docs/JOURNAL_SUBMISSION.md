# Code and data files for journal upload

The private GitHub repository is the author development record. Reviewers should receive the prepared supplementary archives through the journal portal; a private URL alone is not an access method.

| File | Purpose |
| :-- | :-- |
| `Supplementary_Code_v0.2.0_review.zip` | Portable commands, original modules, tests, documentation, provenance and three figure reference PNGs |
| `Supplementary_Data_Tables_v0.2.0_review.zip` | All 38 result tables, genuine climate and CSV inputs, dated records, study boundary and transition raster |
| `Supplementary_Data_Grid_v0.2.0_review.zip` | Genuine JRC monthly 2000 raster used by the original grid audit |
| `Supplementary_Data_Context_v0.2.0_review.zip` | Original national boundary in lossless gzip and source metadata |

Each ZIP is below the 30 MB additional-file size listed in the official Frontiers submission guide. The exact receipt supplies byte sizes and hashes. Extract all four into the same empty folder, then follow `REVIEW_README.md`. Files have one shared root directory. The isolated extraction/run check uses these actual ZIPs.

Attach these four archives as supplementary code/data, plus the compact Supplementary Methods document, the manuscript and the separately requested figure files. Use the archive names above in the portal and retain the manuscript's matching Data and code availability statement. Do not upload the old `Reproducibility.zip` as a substitute: it is historical development material retained locally and in earlier private Git history. Do not upload the entire local author-delivery ZIP as one supplementary file.

The repository release provides private download copies; it is not a journal submission. Public access, a DOI and a reuse license have not been assigned. Author contributions and all-author approval are still required before submission. Recheck the live portal's actual file constraints when submitting.
